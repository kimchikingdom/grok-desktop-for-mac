## 다음에 할 것

### 모든 버튼 상호작용 점검

앱을 실제로 켜고 **화면의 모든 버튼**이 클릭·호버·비활성·키보드에서 정상인지 확인한다. 사이드바를 손본 뒤 히트박스·오버레이·disabled 상태가 어긋날 수 있다.

점검 범위 (빠진 면이 있으면 추가):

- 사이드바: 새 대화, 워크트리, 탭(대화/파일/변경), 필터, 검색, 세션 행(열기·고정·삭제·포크·스플릿), 파일 트리, 최근 파일
- 헤더: 폴더, 모델, 리뷰, 파일 전환, 사용량, 설정, 단축키, 브랜치 복사
- 채팅: 턴 레일, 찾기, 다시 생성, 복사, 경로 링크, 도구 카드, 승인(Y/S/N), 라이트박스
- 입력창: 보내기, 첨부, 받아쓰기, 모드(질문/계획/에이전트), 큐, 옆 질문, 슬래시/멘션
- 리뷰: 다음/이전, stage/revert, 댓글, 미리보기, 범위
- 오버레이: 설정, 단축키, 확인 모달, 명령 팔레트(⌘P / ⌘⇧P)

확인할 것:

- 클릭이 먹고, 핸들러가 기대한 동작을 한다
- hover/active/disabled가 보이고, 죽은 클릭 영역이 없다
- 아이콘만 있는 버튼은 title/aria가 있다
- 좁은 창·호버 오버레이(세션 액션)에서도 누르기 쉽다

깨진 것은 바로 고친다. Playwright UI E2E는 여전히 비목표 — 수동 점검 + 필요하면 기존 단위/보안 테스트만 보강한다.

### 남은 사용량 표시

지금은 한도 초과(429) 본문의 `tokens (actual/limit)`가 있을 때만 헤더에 잔여 토큰이 나온다. 그 전에는 게이지가 비어 있다. CLI/ACP에 남은 사용량 조회 필드가 없다는 전제로 추정치를 만들지 않았다.

구현 시:

- 공식 표면을 다시 확인한다 (`initialize` `_meta`, 세션 이벤트, `/usage`·`/context` 응답, `grok` 문서). 확인된 숫자만 표시한다.
- 구독 잔여(롤링 한도)와 컨텍스트 창 사용량은 섞지 않는다.
- 공식 값이 생기면 429 이전에도 헤더 게이지에 잔여를 보여 준다. 없으면 없는 이유를 유지하고 가짜 퍼센트는 넣지 않는다.

## 동작은 하나 품질이 약한 것

1. **Trusted 일반 쓰기는 자동 허용**이되, 이제 채팅에 자동 허용 카드가 남는다. CLI 자체 쓰기는 여전히 승인 카드 없이 파일이 바뀔 수 있다.
2. **통합 PTY 터미널은 없다.** localhost 미리보기만 명령 출력에서 연다.
3. **스킬·MCP 토글 후 연결을 다시 시작해야** 열린 ACP에 반영된다. 설정에서 다시 시작을 묻는다.
